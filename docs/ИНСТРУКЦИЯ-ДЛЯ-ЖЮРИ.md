# Инструкция для жюри

Система принимает NDTP-телеметрию по TCP, прогнозирует отклонение от расписания
на горизонте **10–15 минут** и показывает диспетчеру транспорт, прогнозы и
инциденты. Для демонстрации нужен один запуск: `make up`.

## Подготовка и запуск

Установите Docker с Compose, Python 3.12+ и GNU Make. Из корня репозитория
проверьте наличие архива `emulator/ndtp-telemetry-emulator.tar`, конкурсных CSV
в `data/raw/` и артефактов модели в `ml/artifacts/`. Подробный список файлов
есть в [инструкции по запуску](../ЗАПУСК.md). Архив и большие CSV
передаются отдельно и не входят в Git.

Если `.env` ещё не создан, выполните:

```bash
cp .env.example .env
make up
```

Команда поднимет PostgreSQL, ML, Backend, Frontend и официальный NDTP-эмулятор.
Она дождётся пакетов пяти терминалов, прогнозов и инцидентов. Январская запись
загружается Backend из исторических CSV и доступна при этом же запуске.

Откройте <http://localhost:8080> и войдите:

```text
Логин: dispatcher
Пароль: transport
```

## Что показать в дашборде

В правой части верхней панели переключаются два источника без перезапуска:

1. **NDTP · поток** — синтетические терминалы эмулятора отправляют пакеты по
   TCP. На карте и в списке видны текущие машины; в карточке выбранной машины
   показаны прогноз и целевая остановка. Риск и инцидент отображаются в блоке
   **«Требуют внимания»**. Прогнозы этого источника помечены как
   **«синтетический план эмулятора»**.
2. **Январь · запись** — исторический день из CSV с картой, списком рейсов и
   управлением временем. По точкам записи рассчитываются прогнозы.
   Январская запись работает в том же приложении и не требует отдельного
   контейнера.

Поток эмулятора показывает полный realtime-контур
`NDTP/TCP → Backend → ML → инцидент → дашборд`. Январская запись показывает
исторические рейсы и работу прогноза на их данных. Синтетический поток не
используется для оценки конкурсной точности.

## Быстрая проверка

| Адрес | Что видно |
|---|---|
| <http://localhost:8080> | оба источника в дашборде |
| <http://localhost:8000/api/v1/health> | состояние Backend |
| <http://localhost:8001/health> | загруженная модель ML |
| <http://localhost:8000/api/v1/metrics> | счётчики пакетов и прогнозов после входа |
| <http://localhost:8000/docs> | Swagger/OpenAPI Backend |

Для проверки контейнеров выполните `docker compose ps`. Если данные не
появились, посмотрите `docker compose logs --tail=200 backend ml frontend`.
Адреса с данными транспорта и метриками требуют входа в дашборд.

После демонстрации остановите приложение и эмулятор командой `make down`.
