# Инструкция для жюри

Система принимает телеметрию по протоколу NDTP/TCP, строит прогноз отклонения
от расписания на горизонте **10–15 минут** и показывает диспетчеру транспорт,
прогнозы и инциденты.

Для демонстрации доступны два независимых источника:

| Режим | Что подаётся | Когда использовать |
|---|---|---|
| Исторический датасет | реальные строки `traffic.csv`, последовательно закодированные в NDTP и отправленные по TCP | основной сценарий проверки на конкурсных данных |
| Эмулятор NDTP организаторов | синтетическая телеметрия пяти терминалов | проверка полного realtime-контура и совместимости с эмулятором |

> Оба режима проходят один рабочий контур: `NDTP/TCP → Backend → ML → прогноз → инцидент → WebSocket → дашборд`.

## Быстрый сценарий: исторический датасет

Этот режим не требует Docker-образа эмулятора организаторов.

1. Установите Docker Desktop или Docker Engine с Compose, а также Python 3.12+
   для управляющих скриптов. Имя команды Python определяется автоматически.
2. В терминале перейдите в корень репозитория.
3. Запустите:

```bash
cp .env.example .env
make up-dataset-replay
```

Команда поднимет PostgreSQL, ML service, Backend, Frontend и сервис replay.
По умолчанию будут выбраны до двух рейсов из `data/raw/validate`, а поток будет
ускорен в 1800 раз. Время внутри NDTP-пакетов остаётся исходным, поэтому
горизонт прогноза 10–15 минут не искажается.

После запуска откройте <http://localhost:8080> и войдите:

```text
Логин: dispatcher
Пароль: transport
```

В правой части верхней панели выберите источник:

- **NDTP · поток** — пакеты из CSV, реально прошедшие через NDTP/TCP и online-инференс;
- **Январь · запись** — ретроспективный просмотр исторического дня с управлением временем.

Статус отправки исторического потока доступен по адресу
<http://localhost:18081/api/status>.

## Альтернативный сценарий: эмулятор NDTP организаторов

Положите переданный организаторами архив по пути:

```text
emulator/ndtp-telemetry-emulator.tar
```

Затем выполните:

```bash
cp .env.example .env   # только если .env ещё не создан
make up
```

Команда загрузит образ `ndtp-telemetry-emulator:1.0`, запустит пять терминалов,
подключит их к Backend по TCP и дождётся появления телеметрии, прогнозов и
активных инцидентов.

Если архив находится в другом месте:

```bash
make up NDTP_EMULATOR_ARCHIVE=/полный/путь/ndtp-telemetry-emulator.tar
```

В дашборде выберите **NDTP · поток**. Этот режим использует синтетические GPS и
синтетический план, поэтому он демонстрирует интеграцию, а не точность на
реальном расписании. Такие прогнозы явно помечены как
**«синтетический план эмулятора»**.

## Где смотреть результат

| Что проверить | Где смотреть |
|---|---|
| Дашборд диспетчера | <http://localhost:8080> |
| Положение и состояние транспорта | вкладка **Карта**, список слева и маркеры на карте |
| Прогноз на 10–15 минут | выбрать терминал; прогноз показан в правой карточке |
| Риск и алерт | блок **«Требуют внимания»**, цвет риска и карточка активного инцидента |
| Табличный список | вкладка **Таблица** |
| Прогнозы в API | <http://localhost:8000/api/v1/predictions> |
| Инциденты в API | <http://localhost:8000/api/v1/incidents> |
| Метрики NDTP и ML | <http://localhost:8000/api/v1/metrics> |
| Swagger/OpenAPI | <http://localhost:8000/docs> |
| Состояние Backend | <http://localhost:8000/api/v1/health> |
| Загруженная модель | <http://localhost:8001/health> |

Защищённые API-адреса открываются после входа в дашборд в том же браузере.
В Swagger нажмите **Authorize** и используйте те же логин и пароль.

Основные поля `/api/v1/metrics`:

| Поле | Значение |
|---|---|
| `ndtp.accepted_packets` | число принятых корректных пакетов |
| `ndtp.invalid_packets` | число отброшенных повреждённых пакетов |
| `ndtp.vehicles` | число терминалов в текущем состоянии Backend |
| `prediction.requests_succeeded` | число успешно рассчитанных прогнозов |
| `prediction.requests_failed` | число ошибок обращения к ML |
| `prediction.packet_to_publish_p95_s` | p95 времени от пакета до публикации прогноза |

### Что должно меняться во время демонстрации

- в списке и на карте появляются терминалы;
- у выбранного терминала отображается прогноз в секундах и время целевой остановки;
- при среднем или высоком риске транспорт попадает в блок
  **«Требуют внимания»** и создаётся инцидент;
- в `/api/v1/metrics` растут `ndtp.accepted_packets` и
  `prediction.requests_succeeded`;
- в `/api/v1/predictions` появляются записи с `source=replay` для исторического
  потока или `source=demo` для эмулятора организаторов.

## Быстрая проверка из терминала

```bash
docker compose ps
curl http://localhost:8000/api/v1/health
curl http://localhost:8001/health
```

Для защищённых методов сначала получите cookie:

```bash
curl -c cookies.txt -X POST http://localhost:8000/api/v1/auth/token \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'username=dispatcher&password=transport'

curl -b cookies.txt http://localhost:8000/api/v1/predictions
curl -b cookies.txt http://localhost:8000/api/v1/incidents
curl -b cookies.txt http://localhost:8000/api/v1/metrics
```

## Остановка и повторный запуск

```bash
make down
```

После `make down` можно запустить любой из двух режимов заново. Переключаться
между ними вручную не нужно: `make up` останавливает dataset replay, а
`make up-dataset-replay` останавливает официальный эмулятор.

## Если данные не появились

1. Проверьте контейнеры: `docker compose ps`.
2. Посмотрите логи: `docker compose logs -f backend ml frontend`.
3. Для исторического режима откройте <http://localhost:18081/api/status>.
4. Для причины отсутствия прогноза откройте
   <http://localhost:8000/api/v1/predictions/statuses> после авторизации.
5. Убедитесь, что порты `8000`, `8001`, `8080`, `9201` и, для replay, `18081`
   не заняты другими приложениями.

Полная техническая инструкция: [`ЗАПУСК.md`](../ЗАПУСК.md).
