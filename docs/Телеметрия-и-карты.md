## Backend и эмулятор

Образ организаторов можно положить в корень проекта или `emulator/` (оба пути
исключены из Git). Запуск Backend, Frontend и официального NDTP-эмулятора:

```bash
make up-ndtp
```

Если `make` в Windows не установлен, те же команды в PowerShell:

```powershell
docker compose up -d --build backend frontend
python scripts/start_official_emulator.py
```

Команда применяет [`emulator/official-demo-config.json`](emulator/official-demo-config.json)
с двумя генерируемыми терминалами и проверяет приём пакетов в Backend. Свой
конфиг можно загрузить командой:

```bash
python scripts/start_official_emulator.py --config emulator/config.json
```

Подробности протокола — в
[`docs/Emulator-and-Telematic-Packets-Specification.md`](docs/Emulator-and-Telematic-Packets-Specification.md).

Официальный эмулятор генерирует синтетическое движение. В NDTP есть GPS,
скорость, курс и пройденное расстояние (`track`/одометр), но нет идентификатора
маршрута или перечня остановок. Синяя линия на основной NDTP-карте — след
**уже принятых** GPS-пакетов выбранного терминала. Для проверки маршрутов по
реальным проездам используйте январский CSV → NDTP replay ниже.

Для расширенного дебага доступен второй, независимый эмулятор, который
последовательно воспроизводит реальные строки конкурсного `traffic.csv` через
тот же NDTP/TCP-контур. Он запускается отдельным Docker-профилем и никак не
меняет эмулятор организаторов:

```bash
make up-dataset-replay
```

Управление replay и примеры запросов описаны в
[`emulator/dataset_replay/README.md`](emulator/dataset_replay/README.md).

В верхней панели диспетчер выбирает «NDTP · поток» или «Январь · запись».
Выбор действует одновременно для карты и таблицы. Январская запись идёт
автоматически в масштабе 1× с первого восстановленного рейса (02:18 в текущей
записи), после конца дня начинается заново; кнопка рядом с выбором
источника возвращает её к началу. Скорость и ручная перемотка не показываются.
Прогнозы рассчитываются по исходным январским `T`: в ML передаются только
пакеты с `event_time` и `receive_time` не позже T. Факт прибытия появляется
в карточке транспорта только после времени этого прибытия. Значки движения,
стоянки и потери координат общие с NDTP-картой; красная обводка означает
прогноз опоздания.
Рядом с движущимися маркерами видна скорость, а при прогнозе задержки от двух
минут — белая плашка с величиной опоздания.
В январском режиме координаты считаются устаревшими через две минуты без
нового GPS, а машина уходит из списка «на линии» через 15 минут без данных.

Маршруты восстанавливаются из повторяющейся последовательности координат
`test/schedule.csv`, затем каждая плановая точка сверяется с GPS в окне ±8 минут
(расстояние до 120 м). Проход показывается подтверждённым при ≥5 совпадениях и
≥50% совпавших точек. В текущем январском CSV это 105 проходов, 692 уникальные
GPS-подтверждённые координаты и 23 машины с валидным GPS из 30. План есть
только у 13 машин; для одной из них GPS не подтвердил маршрут. Идентификатора
публичного маршрута в данных нет, поэтому интерфейс показывает ID ТС и номер
восстановленного прохода. Плановая линия и остановки валидного рейса видны с
его начала; GPS-подтверждение и факт прибытия не раскрываются раньше времени.
Восстановление маршрута не входит в признаки ML.

## Frontend

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm dev                  # http://localhost:5173, прокси на backend :8000
```

Прод-сборка в Docker: `make up-frontend` (nginx на :8080), разработка в контейнере —
`make up-frontend-dev`. Структура папок, env-переменные и что уже подключено — в
[`frontend/README.md`](frontend/README.md).

## ML

```bash
cd ml
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev,models]'
```

Дальнейшие команды обучения и API описаны в [`ml/README.md`](ml/README.md). Пока ML-файлы являются каркасом, поэтому сначала следует согласовать feature contract и target.

## Весь стек целиком

```bash
cp .env.example .env
docker compose up --build
```

| Сервис | Адрес |
| --- | --- |
| Дашборд | <http://localhost:8080> |
| Swagger API | <http://localhost:8000/docs> |
| Health check | <http://localhost:8000/api/v1/health> |

Демо-вход диспетчера: `dispatcher` / `transport`. Перед деплоем замените пароль
и `AUTH_JWT_SECRET` в `.env`.
