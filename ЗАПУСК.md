# Запуск проекта

Ниже описан запуск готовой системы. Для короткой демонстрации используйте
отдельную [инструкцию для жюри](docs/ИНСТРУКЦИЯ-ДЛЯ-ЖЮРИ.md).

## 1. Требования

- Docker Desktop либо Docker Engine;
- Docker Compose v2 (`docker compose`);
- Git;
- Python 3.12+ для управляющих скриптов `make up` и
  `make up-dataset-replay`; Makefile автоматически найдёт `python3`, `python`
  или версионированную команду в `PATH`;
- `make` (macOS/Linux; на Windows удобно использовать WSL).

Все команды выполняются из корня репозитория.

Проверьте основные входные файлы:

```bash
test -f data/raw/validate/traffic.csv
test -f data/raw/validate/schedule_plan.csv
test -f data/raw/validate/points.csv
test -f ml/artifacts/release_manifest.json
```

Создайте локальный файл настроек:

```bash
cp .env.example .env
```

Для локальной демонстрации значения по умолчанию подходят без изменений.

## 2. Выбор режима запуска

Не запускайте оба источника телеметрии одновременно. Выберите один режим.

### Режим A — исторический датасет через NDTP

Рекомендуемый режим для проверки проекта на конкурсных данных:

```bash
make up-dataset-replay
```

Команда:

1. останавливает официальный эмулятор, если он был запущен;
2. собирает и запускает PostgreSQL, ML service, Backend и Frontend;
3. запускает сервис CSV → NDTP;
4. начинает отправку до двух подходящих рейсов из `data/raw/validate`.

По умолчанию подача ускорена в 1800 раз. Выбрать рейсы и скорость можно через
переменные окружения:

```bash
REPLAY_TR_IDS=131672,122048 REPLAY_SPEED=600 make up-dataset-replay
```

Статус replay: <http://localhost:18081/api/status>.

### Режим B — официальный NDTP-эмулятор

Для этого режима нужен архив Docker-образа организаторов, который не хранится
в Git. Положите его сюда:

```text
emulator/ndtp-telemetry-emulator.tar
```

Запустите:

```bash
make up
```

Команда загрузит образ при необходимости, поднимет приложение, подключит пять
синтетических терминалов и автоматически проверит появление пакетов, прогнозов
и инцидентов.

Для архива в другом каталоге:

```bash
make up NDTP_EMULATOR_ARCHIVE=/полный/путь/ndtp-telemetry-emulator.tar
```

`make up-ndtp` — синоним `make up`.

### Режим C — только сервисы, без источника телеметрии

Подходит для разработки API или ручной подачи NDTP на TCP-порт `9201`:

```bash
docker compose up -d --build --wait
```

## 3. Проверка готовности

```bash
docker compose ps
curl http://localhost:8000/api/v1/health
curl http://localhost:8001/health
```

Ожидается:

- контейнеры имеют состояние `running`/`healthy`;
- Backend возвращает статус `ok`;
- ML health возвращает имя, версию и сведения о загруженной модели.

## 4. Адреса приложения

| Адрес | Назначение | Доступ |
|---|---|---|
| <http://localhost:8080> | дашборд диспетчера | логин и пароль |
| <http://localhost:8000/docs> | Swagger Backend | авторизация внутри Swagger |
| <http://localhost:8000/redoc> | ReDoc Backend | схема API |
| <http://localhost:8000/api/v1/health> | health Backend | публичный |
| <http://localhost:8001/health> | health и версия ML | публичный |
| <http://localhost:8000/api/v1/metrics> | счётчики NDTP и задержки inference | после входа |
| <http://localhost:18081/docs> | Swagger dataset replay | только в режиме A |
| `localhost:9201` | TCP-сервер NDTP | бинарный протокол |

Демо-учётная запись:

```text
Логин: dispatcher
Пароль: transport
```

Перед внешним размещением обязательно замените в `.env` значения
`AUTH_BOOTSTRAP_PASSWORD`, `AUTH_JWT_SECRET` и параметры PostgreSQL.

## 5. Проверка защищённого API

Авторизация принимает OAuth2 form-data, а не JSON:

```bash
curl -c cookies.txt -X POST http://localhost:8000/api/v1/auth/token \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'username=dispatcher&password=transport'
```

После этого:

```bash
curl -b cookies.txt http://localhost:8000/api/v1/vehicles
curl -b cookies.txt http://localhost:8000/api/v1/predictions
curl -b cookies.txt http://localhost:8000/api/v1/incidents
curl -b cookies.txt http://localhost:8000/api/v1/metrics
```

Причины, по которым отдельный терминал ещё не получил прогноз:

```bash
curl -b cookies.txt http://localhost:8000/api/v1/predictions/statuses
```

## 6. Управление

Посмотреть логи всех сервисов:

```bash
docker compose logs -f
```

Логи основных компонентов:

```bash
docker compose logs -f backend ml frontend
```

Остановить проект и официальный эмулятор:

```bash
make down
```

Пересобрать образы после изменения кода:

```bash
docker compose build
```

Повторно запустить уже поднятый исторический replay:

```bash
make replay-start
```

## 7. Что сохраняется между перезапусками

Прогнозы и жизненный цикл инцидентов сохраняются в PostgreSQL и
восстанавливаются после перезапуска Backend. Docker volume можно удалить только
явно, если требуется полностью чистый стенд:

```bash
docker compose down -v
```

Эта команда удаляет локальную БД проекта. Конкурсные CSV и артефакты модели в
репозитории она не затрагивает.

## 8. Типовые проблемы

### `Python 3.12+ not found in PATH`

Установите Python 3.12+ так, чтобы его команда была доступна в терминале.
Если интерпретатор находится вне `PATH`, запустите
`make up PYTHON=/путь/к/python`.

### Не найден образ эмулятора

Сообщение `NDTP image missing` означает, что для режима B не найден архив
`emulator/ndtp-telemetry-emulator.tar`. Передайте правильный путь через
`NDTP_EMULATOR_ARCHIVE` либо используйте режим A.

### Контейнер не стал healthy

```bash
docker compose ps
docker compose logs --tail=200 backend ml postgres
```

Чаще всего причина — занятый порт, недоступный входной CSV или повреждённый
артефакт модели.

### Телеметрия есть, но прогноза нет

Проверьте `/api/v1/predictions/statuses`. Для прогноза Backend должен
сопоставить терминал с расписанием, определить целевую остановку в интервале
`(T + 10 минут, T + 15 минут]` и получить достаточно данных для признаков.

### Порты уже заняты

Измените соответствующие значения в `.env`: `FRONTEND_PORT`, `BACKEND_PORT`,
`ML_SERVICE_PORT`, `NDTP_PORT`, `REPLAY_API_PORT`. Если меняется порт Backend,
учтите, что управляющим скриптам также может потребоваться `BACKEND_URL`.

## 9. Локальные проверки для разработчиков

```bash
python3 scripts/verify_submission.py
python3 scripts/verify_model_parity.py
cd backend && python3 -m pytest -q
cd ../ml && python3 -m pytest -q
cd ..
pnpm -C frontend build
```

Проверка parity обращается к запущенному ML API. Для сборки frontend нужны
Node.js и `pnpm`; для обычного Docker-запуска они на хосте не требуются.
