# Запуск проекта

Здесь описан один способ поднять демонстрацию целиком: `make up`. Он запускает
сервисы, официальный NDTP-поток и доступную в том же дашборде январскую запись.

## Что нужно до запуска

- Docker Desktop или Docker Engine с командой `docker compose`;
- Python 3.12+ в `PATH` и GNU Make; на Windows используйте PowerShell с
  установленным `make`, на Linux/macOS — обычный терминал;
- архив эмулятора организаторов `emulator/ndtp-telemetry-emulator.tar`;
- конкурсные файлы `data/raw/validate/schedule_plan.csv` и
  `data/raw/validate/traffic.csv` для Backend/ML;
- файлы `data/raw/test/schedule.csv`, `data/raw/test/traffic.csv` и
  `data/raw/labels/labels_test.csv` для январской записи;
- артефакты модели в `ml/artifacts/`, включая `release_manifest.json`.

Архив эмулятора и большие CSV не хранятся в Git. Все команды выполняются из
корня репозитория.

## Запуск

Если `.env` ещё не создан, скопируйте пример. Существующий `.env` не
перезаписывайте.

```bash
cp .env.example .env
make up
```

`make up` загружает образ эмулятора из архива при необходимости, собирает и
поднимает PostgreSQL, ML, Backend и Frontend, запускает пять терминалов
эмулятора и дожидается телеметрии, прогнозов и инцидентов. Backend также
загружает январскую запись из CSV. Оба источника выбираются в интерфейсе без
дополнительного запуска.

## Проверка в браузере

Откройте <http://localhost:8080> и войдите под демонстрационной учётной записью:

```text
Логин: dispatcher
Пароль: transport
```

В верхней панели переключите источник:

- **NDTP · поток**: пять синтетических терминалов посылают пакеты по TCP на
  Backend; доступны текущие позиции, прогнозы и инциденты.
- **Январь · запись**: Backend показывает исторические рейсы из CSV; можно
  управлять временем записи и получать прогнозы по её точкам.

Январская запись доступна при том же `make up`. Она загружается из файлов, а
не из отдельного контейнера. Синтетический NDTP-поток служит демонстрацией
realtime-контура и не является конкурсной оценкой MAE.

Полезные адреса:

| Адрес | Назначение |
|---|---|
| <http://localhost:8080> | дашборд |
| <http://localhost:8000/api/v1/health> | состояние Backend |
| <http://localhost:8001/health> | состояние и версия ML |
| <http://localhost:8000/docs> | Swagger/OpenAPI Backend |
| <http://localhost:8000/api/v1/metrics> | счётчики NDTP и прогнозов после входа |
| `localhost:9201` | TCP-порт NDTP |

## Если запуск не удался

- `Python 3.12+ not found in PATH`: проверьте версию `python --version`.
  Если Python установлен вне `PATH`, укажите путь к нему через
  `make up PYTHON=/путь/к/python`.
- `NDTP image missing`: проверьте путь
  `emulator/ndtp-telemetry-emulator.tar`.
- Контейнер не стал healthy: выполните `docker compose ps` и
  `docker compose logs --tail=200 backend ml postgres frontend`.
- Телеметрия есть, но нет прогноза: после входа проверьте
  <http://localhost:8000/api/v1/predictions/statuses>. Для прогноза нужен
  целевой пункт в интервале (T + 10 минут, T + 15 минут].
- Если порт занят, проверьте `FRONTEND_PORT`, `BACKEND_PORT`,
  `ML_SERVICE_PORT` и `NDTP_PORT` в `.env`.

Чтобы остановить приложение и эмулятор, выполните `make down`.
