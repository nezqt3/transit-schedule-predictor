# 🚀 Запуск демо — инструкция для жюри

**Полный прогон занимает ~3 минуты.** Нужны Docker и распакованный clone репозитория.

> Данные соревнования (`data/raw/...`) в Git не коммитятся — перед запуском
> положить их локально в структуру `data/raw/train|test|validate|labels`.

---

## 1. Быстрый старт (рекомендуемый путь)

```bash
cp .env.example .env
make up-dataset-replay
```

Одна команда:

1. поднимает **backend + ML-сервис + дашборд + replay-сервис**;
2. **сама запускает NDTP-поток** по реальному рейсу из валидационного датасета
   (темп 1:1, от первого пакета до конца записи).

Пакеты начинают появляться в backend в течение ~10 секунд.

Открыть **<http://localhost:8080>**, войти:

| Логин | Пароль |
| --- | --- |
| `dispatcher` | `transport` |

## 2. Карта портов

| Сервис | Порт | Что там |
| --- | --- | --- |
| 🖥️ Дашборд диспетчера | `:8080` | карта, терминалы, прогнозы, алерты |
| 📖 Backend API + Swagger | `:8000/docs` | живые эндпоинты, можно тыкать Try it out |
| 🧠 ML-сервис | `:8001` | `GET /health`, `POST /predict` |
| 📡 NDTP (TCP-вход backend) | `:9201` | сюда эмуляторы шлют пакеты |
| 🔁 Dataset-replay API | `:18081/docs` | выбрать рейсы, старт/пауза/скорость |
| 🤖 Эмулятор организаторов | `:18080` | только при `make up-ndtp` |

## 3. Где что смотреть на дашборде

| Что | Где |
| --- | --- |
| 🔮 **Прогноз задержки на 10–15 мин** | Клик по терминалу (справа карта, слева список) → карточка «Прогноз 10–15 мин» — секунды до целевой остановки и версия модели |
| ⚠️ **Алерты** | В списке терминалов сверху группа **«Требуют внимания»**; фильтр «Тревога»; на карте красные маркеры (прогноз ≥ 2 мин опоздания), «Нет координат», «Устарели координаты» |
| 📊 **Сводка парка** | Счётчики под картой: терминалов / на карте / требуют внимания |
| 📈 **Метрики качества (MAE)** | Раздел **«Исторический прогон»** — <http://localhost:8080/replay> |
| 💨 **Скорость, история, GPS-след** | В карточке терминала: тренд скорости по последним точкам |

### Как читать прогноз

`predicted_delay_s` — отклонение от расписания в секундах на целевой остановке
через 10–15 минут:

```text
+143 с → опоздает на 2,5 минуты
 −40 с → приедет раньше графика
   0 с → точно по расписанию
```

Горизонт прогноза фиксирован: для момента `T` целевая остановка — первая
плановая точка в интервале `(T+10 мин; T+15 мин]`. ML-сервис использует только
данные, доступные на момент `T`, — target leakage нет по построению.

### Что считается алертом

Алерты вычисляет **backend** из прогноза и статуса телеметрии, отдельного
REST-эндпоинта для инцидентов нет — вся фильтрация живёт в дашборде. Порог
тревоги на карте: прогноз **≥ 120 секунд** опоздания.

## 4. Метрики — страница «Исторический прогон»

<http://localhost:8080/replay>

Страница берёт **тестовый январский день с размеченным фактом** (`labels_test`,
353 точки) и проигрывает его со скоростью до **1800×** — весь день за минуту.
По ходу считается и показывается:

| Показатель | Смысл |
| --- | --- |
| **MAE модели** | главная метрика соревнования, секунды; чем меньше — тем лучше |
| **MAE baseline `cur_dev_s`** | ориентир: «прогнозировать текущее отклонение» |
| **Прогнозов к T** | сколько прогнозных точек уже рассчитано |
| Таблица «Прогноз / Факт / Ошибка» | по каждой остановке: план, прогноз, факт, абсолютная ошибка |

Ожидаемый порядок на test: **~84 с у модели против ~92 с у baseline**
(CatBoost-ансамбль из 5 сидов). Полные метрики и история экспериментов —
[docs/ML-эксперименты.md](docs/ML-эксперименты.md).

> ⚙️ В контейнерах по умолчанию работает модель `baseline` (без тяжёлых
> артефактов), чтобы стек поднимался за секунды. Чтобы показать обученный
> CatBoost: положить артефакт в `ml/artifacts/` и в `.env` поставить
> `MODEL_NAME=catboost`, затем `docker compose up -d --build ml`.

## 5. Подать поток вручную / выбрать рейс

```bash
make up-dataset-replay        # если контейнеров ещё нет
make replay-start             # дефолт: лучший валидный рейс из validate, темп 1:1
```

Варианты подачи (переменные окружения читает `scripts/start_dataset_replay.py`):

```bash
REPLAY_TR_ID=131672 make replay-start              # конкретный рейс
REPLAY_SPEED=60 make replay-start                  # ускорить всю шкалу в 60 раз
REPLAY_ALL_VALID=1 make replay-start               # все машины с валидным GPS
REPLAY_ALL=1 REPLAY_VALID_ONLY=0 make replay-start # и пакеты без координат тоже
REPLAY_TIME_MODE=original REPLAY_SPEED=180 make replay-start  # исходные январские часы
```

Через API replay-сервиса — так же, как из `http://localhost:18081/docs`:

```bash
# найти подходящие рейсы (виден список с числом GPS-пакетов)
curl 'http://localhost:18081/api/scenarios?dataset=validate&limit=10'

# запустить конкретные рейсы в реальном темпе
curl -X POST http://localhost:18081/api/replay/start \
  -H 'Content-Type: application/json' \
  -d '{"dataset":"validate","tr_ids":[131672],"time_mode":"shift_to_now","valid_locations_only":true}'

curl http://localhost:18081/api/status              # состояние и счётчики
curl -X POST http://localhost:18081/api/replay/pause
curl -X POST http://localhost:18081/api/replay/resume
curl -X POST http://localhost:18081/api/replay/stop
```

Режимы времени:

- `shift_to_now` — интервалы исходной записи сохраняются, но первый пакет
  приходит «в сейчас». **Рекомендуемый для live-демо.**
- `original` — исходные timestamps из CSV (январские часы = МСК), удобно для
  точного исторического дебага.

До 100 рейсов в одном прогоне; на каждый уникальный `unit_id` — своё TCP-соединение
и отдельный NDTP-handshake, общий scheduler сохраняет реальные интервалы между пакетами.

## 6. Альтернатива: официальный эмулятор организаторов

```bash
make up-ndtp
```

Поднимает backend + frontend и запускает Docker-образ `ndtp-telemetry-emulator`
(файл `emulator/ndtp-telemetry-emulator.tar`, в Git не лежит — положить вручную
в корень или `emulator/`), применяет `emulator/official-demo-config.json`
и проверяет, что backend получил пакеты. Свой конфиг:
`python scripts/start_official_emulator.py --config emulator/config.json`.

⚠️ Этот эмулятор генерирует **синтетическое** движение: в NDTP есть координаты,
скорость и курс, но **нет привязки к маршруту и расписанию**, поэтому карточка
прогноза честно показывает **«Пока недоступен»**. Демонстрировать прогнозы и
метрики нужно путём из раздела 1 (dataset-replay + страница `/replay`).

## 7. Проверить, что всё живо, без браузера

```bash
curl http://localhost:8000/api/v1/health

# токен в HttpOnly-куку, дальше все запросы с -b
curl -c /tmp/j -X POST http://localhost:8000/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"username":"dispatcher","password":"transport"}'

curl -b /tmp/j http://localhost:8000/api/v1/vehicles | head -c 400
curl -b /tmp/j http://localhost:8000/api/v1/predictions | head -c 400
curl -b /tmp/j http://localhost:8000/api/v1/replay/fleet | head -c 400
```

## 9. Диагностика

| Симптом | Что делать |
| --- | --- |
| Дашборд пустой: «Телеметрия пока не поступала» | Поток не запущен: `make replay-start`; статус — `curl http://localhost:18081/api/status` |
| Карточка терминала: «Пока недоступен» | У терминала нет привязки к расписанию (это официальный эмулятор) — см. раздел 6 |
| `401 Unauthorized` на `/api/v1/*` | Все эндпоинты, кроме `/health` и `/auth/token`, требуют JWT-куку — войти через дашборд или получить токен (раздел 7) |
| Порт `8080` / `9201` / `18081` занят | Поменять `FRONTEND_PORT` / `REPLAY_API_PORT` в `.env` либо пробросы в `docker-compose.yml` |
| «NDTP image missing» у `make up-ndtp` | Положить `ndtp-telemetry-emulator.tar` в корень репо или в `emulator/` |
| ML-сервис не отвечает | `curl http://localhost:8001/health`; логи — `docker compose logs -f ml`. Backend при этом живёт и продолжает показывать телеметрию |
| Что-то упало | `docker compose logs -f backend` и `make logs-dataset-replay` |
| Остановить всё | `docker compose down` (replay-профиль — `docker compose --profile replay down`) |
