# Backend

FastAPI принимает NDTP-пакеты по TCP `:9201`, хранит до 150 недавних пакетов
на терминал, выбирает первую плановую остановку в `(T+10 мин, T+15 мин]`,
вызывает отдельный ML-сервис и публикует прогноз/инцидент через REST и
WebSocket. Прогноз запускается автоматически после принятого пакета. Ручной
`POST /api/v1/predictions` остаётся диагностическим маршрутом.
Частота вызовов на машину задаётся `PREDICTION_INTERVAL_S`, общий максимум
одновременных запросов к ML — `ML_MAX_IN_FLIGHT`.

План и соответствие терминала рейсу читаются из `RUNTIME_SCHEDULE_PATH` и
`RUNTIME_TRAFFIC_PATH`. `SOURCE_TIMEZONE` определяет зону CSV без UTC-offset.
Для архивного потока `RUNTIME_POINTS_PATH` может дать опубликованный входной
`cur_dev_s` не раньше его `T`; в живом потоке отклонение берётся лишь из
подтверждённой GPS-остановки. При недостатке данных `/predictions/statuses`
показывает причину пропуска без выдуманного нулевого прогноза.

## API

Публичны `GET /api/v1/health` и документация `/docs`, `/redoc`,
`/openapi.json`. После входа доступны:

| Маршрут | Назначение |
|---|---|
| `GET /api/v1/vehicles`, `/{unit_id}` | Последние NDTP-состояния |
| `GET /api/v1/predictions`, `/{tr_id}/latest`, `/statuses` | Прогнозы и статусы без прогноза |
| `GET /api/v1/incidents`, `/{incident_id}` | Активные и завершённые инциденты |
| `GET /api/v1/metrics` | Счётчики NDTP, ML и очереди WS |
| `WS /api/v1/ws` | `vehicle_update`, `prediction_update`, `incident`, `heartbeat` |
| `/api/v1/replay/*` | Отдельная ретроспективная диагностика при её явном включении |

Вход: `POST /api/v1/auth/token` с полями `username` и `password` в
`application/x-www-form-urlencoded`. JWT возвращается в ответе и HttpOnly
cookie; CLI может использовать `Authorization: Bearer <token>`. Локальные
демо-данные: `dispatcher` / `transport`.

## Хранение и деградация

Последняя телеметрия хранится в ограниченной памяти процесса. Прогнозы и
жизненный цикл инцидентов сохраняются в PostgreSQL и восстанавливаются после
перезапуска Backend. Если БД временно недоступна, Backend продолжает принимать
NDTP и временно работает с прогнозами и инцидентами в памяти; вход и
защищённые операции недоступны до восстановления подключения. При недоступном
ML прежний прогноз помечается `stale`, а новые NDTP-пакеты продолжают
приниматься.

Локальные проверки: `cd backend && python -m pytest -q`. Сквозной путь с
реальной выбранной моделью без Docker: `python scripts/smoke_ndtp_ml.py` из
корня проекта. Порядок контейнерного запуска — [`ЗАПУСК.md`](../ЗАПУСК.md).
